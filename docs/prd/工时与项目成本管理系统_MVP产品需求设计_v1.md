# 工时与项目成本管理系统 · MVP 产品需求设计

| 项目 | 内容 |
|---|---|
| 版本 / 日期 | v1.0 / 2026-09-05 |
| 依据 | [工时与项目成本管理系统 PRD v1.3](工时与项目成本管理系统_PRD_v1.md)（文件名仍为 `_PRD_v1.md`） |

| MVP 定义 | 在 1–2 个部门跑通真实填报、事实审批、标准成本与人员负荷分析、一次月度封账及修订的最小完整产品 |
| 使用方式 | 已确认业务口径继承原 PRD；本文件新增的页面组织、交互、指标定义、权限范围细化与交付拆分属于 MVP 设计方案，不覆盖原 PRD |

## 1. 首版要交付的价值

员工用不超过 3 分钟说明一天的时间去向；负责人能核实投入，并在同一套数据上回答两个同等重要的问题：

1. **项目消耗了多少投入？** 看已确认项目工时、标准人工成本、标准现场成本，以及尚未确认的数据。
2. **人员时间去了哪里？** 看项目工作、非项目工作、已确认待分配时间及持续超载；把漏填、待审批与实际低负荷区分开。

首版形成一条完整链路：

**现有企微身份登录 → 每日记录 → 按周、按对象送审 → 核实工时与现场日 → 管理者查看分析 → 月度封账 → 必要时授权更正并发布修订版。**

不增加任务管理、预算管理或人员排期。管理者依据报告在现有会议中安排工作，MVP 不另建派工、绩效或经营行动跟踪系统。

### 1.1 MVP 的取舍

精简页面数量、配置复杂度和重复录入，不精简会影响数据可信度的规则。原 PRD 要求的五项报表能力保留，合并成三个分析视图；封账虽然在原 PRD 标为 P1，但属于首版试点的完整闭环，不能等到正式月报产生后再补。

| 范围 | MVP 交付方式 | 取舍与边界 |
|---|---|---|
| 登录与身份 | 接入现有企微自建应用 SSO 和已打通的 UserID—工号关联 | 不建设另一套账号密码、身份映射后台 |
| 每日填报 | 一个日编辑页，覆盖工作、待分配、请假展示、现场日 | 不拆成日报、加班申请、出差工时三套表单 |
| 每周送审 | 一次提交预览，系统按对象拆包并回避本人 | 员工不选择审批流程、不手工分发 |
| 工时及现场审批 | 一个审批详情页，支持整包及条目处理 | 保留独立现场日、部分驳回、转交、争议处理 |
| 人员分析与流程合规 | 同一视图中的“时间负荷 / 填报与审批”两个页签 | 不做独立管理大屏 |
| 项目成本 | 汇总、人员、条目逐级查看，支持正式月报版本 | 不接真实工资，不算预算差异和毛利 |
| 现场复核 | 同一台账呈现现场日、时间占比和 OA 比对 | 不做独立占比报表页面，不接报销或定位 |
| 月度结算 | 一个封账工作台，处理未决、解锁范围和报告版本 | 不做通用财务结账系统 |
| 主数据 | 简单列表、编辑表单、Excel 导入与批量调整 | 组织合并、拆分、划转通过现有维护功能组合完成；专用组织变更向导后置 |
| 提醒与参数 | 内置业务规则逐条配置开关、时间、阈值、收件范围和模板 | 不做可视化规则编排器，参数调整无需发版 |
| OA 集成 | 项目、请假、出差三个固定数据接入；保留手工与 Excel 兜底 | 接口联调并行推进，不做通用数据集成平台 |
| 输出与运维 | Excel 导出、操作留痕、每日备份、私有化部署 | 不增加 PDF 模板编辑、短信、多渠道通知 |

专用组织变更向导后置，不意味着允许覆盖历史归属。组织调整仍须明确生效及历史处理方式、记录操作依据；已封账月份的变更走授权修订。

### 1.2 明确不进入 MVP

- 任务、WBS、里程碑、项目预算、合同收入、毛利和真实薪酬。
- WPS 历史日报迁移、差旅报销、GPS 打卡、OA 出差单前置拦截。
- AI 自动编写工作内容、自动补足工时、自动推定待分配、自动裁定争议。
- 自定义审批流程、通用报表设计器、企业微信组织结构自动同步。
- 岗位维度费率、原生手机 App、独立人员排期与绩效系统。

## 2. 角色、入口与页面结构

采用一套适配手机和电脑的 Web 应用。企微负责入口、登录与消息；业务审批在本系统完成。普通员工优先使用手机填报，负责人可在手机处理单个审批包，集中处理待办、分析和管理以电脑为主。

### 2.1 用户进入系统后先看到什么

| 用户 | 对应入口的主要内容 | 最重要的操作 |
|---|---|---|
| 所有员工，包括兼任管理角色的人 | 我的工时：今天及本周完成情况 | 补齐今天、处理驳回、提交上周 |
| 有审批职责的人 | 我的工时上方另显待审批数量；企微审批消息直达指定待办 | 查看原始记录、通过或说明驳回原因 |
| PM | 分析中的本人项目成本 | 找到投入变化及未决记录，查看本项目人员明细 |
| 部门负责人 / 分管领导 | 所辖人员负荷、所辖主责项目成本 | 区分真实待分配、超载及数据不完整 |
| 公司领导 | 全公司分析 | 比较项目投入，查看人员时间构成与异常 |
| 管理员 | 管理中的待处理异常与基础配置 | 补齐主数据、处理接入异常、执行授权转交 |

多角色权限叠加，按功能显示入口，不要求用户切换“员工身份 / PM 身份”。企微消息经过登录及权限校验后定位对应日期、审批包或异常；没有权限时给出明确提示。

### 2.2 页面清单

一级导航保持四项：**我的工时、待我审批、分析、管理**。没有权限的入口隐藏；个人负荷在“我的工时”内查看，不因此开放管理报表。

| 编号 | 页面 / 视图 | 内容边界 | 主要终端 |
|---|---|---|---|
| P01 | 我的工时 | 周概览、日编辑、提交预览、本人记录及更正入口 | 手机优先 |
| P02 | 待我审批 | 待办列表、审批详情、已处理记录、相关争议 | 手机 / 电脑 |
| P03 | 分析 · 人员与执行情况 | 人员负荷热力图、填报与审批合规两个页签 | 电脑 |
| P04 | 分析 · 项目标准成本 | 项目汇总、人员与条目详情、报告版本选择 | 电脑 |
| P05 | 分析 · 现场日复核 | 现场日台账、项目工时占比、OA 比对 | 电脑 |
| P06 | 管理 · 月度封账 | 封账概览、未决、解锁及修订任务、月报版本 | 电脑 |
| P07 | 管理 · 人员与组织 | 身份状态、部门、负责人、职级历史、批量调整 | 电脑 |
| P08 | 管理 · 归集对象 | 项目、非项目对象、审批配置、待办转交 | 电脑 |
| P09 | 管理 · 费率标准 | 职级及现场日标准、生效版本 | 电脑 |
| P10 | 管理 · 数据接入 | 导入、同步记录、异常及映射处理 | 电脑 |
| P11 | 管理 · 系统设置 | 工作日历、业务参数、提醒规则、审计查询 | 电脑 |

“管理”中的具体页面仍逐项授权：部门负责人可维护允许范围内的非项目对象、授权解锁；费率读取者能查看只读标准。看到管理入口不代表成为系统管理员。

## 3. P01：员工填报与周提交

### 3.1 周概览与日编辑

默认打开今天，上方展示完整自然周及每日状态。每个日期同时显示时间是否完整、审批进度；不能只用一个“已完成”状态掩盖待审批或驳回。

当上周仍有待提交记录时，在今天上方显示“上周还有记录待提交”，进入上周预览；不把周末投入误放入本周。支持切换历史日期，已封账日期只读并提供申请补录或更正入口。

日编辑页的最小布局：

```text
我的工时                       9 月 4 日 周五
本周  一  二  三  四  [五]  六  日

应填 8h       已说明 8h       尚差 0h
实际工作 5h   待分配 3h       请假 0h
状态：草稿，尚未送审

当天地点      [在司] [现场（项目出差）]
选择现场后：归属项目、现场事由、现场日状态

A 项目        4h     接口联调及失败原因排查……
部门事务      1h     整理部门月度经营会议材料……
待分配        3h     暂无任务安排

[添加记录]                    [复制上一工作日]
                         [保存草稿] [查看周提交]
```

上图内容为交互示意，不代表生产默认数据。普通员工页面不显示人工费率、现场单价或任何成本金额。

### 3.2 输入字段与行为

| 区域 | 字段 / 交互 | 产品规则 |
|---|---|---|
| 日期与基数 | 工作日期、应填基数、请假时数、数据更新时间 | 基于工作日历及 OA 已审批请假计算；请假只读，不能由员工随手改成休假 |
| 地点 | 在司 / 现场 | 未设置时展示在司选项；复制昨日不继承现场日，避免误记连续出差 |
| 现场 | 归属项目、事由 | 每人每天最多一个项目；支持交通、必要驻留；零工作日及同日多项目需说明事由 |
| 工作记录 | 归集对象、小时数、内容 | 小时数 >0，按 0.5h 步长，快捷 1 / 2 / 4 / 8h；实际工作内容 10–200 字，不与前一日完全重复 |
| 待分配 | 部门预置对象、小时数、可补充说明 | 员工明确选择并确认；预置“暂无任务安排”，不套用工作内容校验 |
| 常用选择 | 我的项目、我的部门事务、全部可选对象 | 我的项目优先列最近使用及本人负责的项目；近 30 天频次排序，不为此增加项目成员维护流程 |
| 复制 | 复制上一工作日的对象和小时数 | 实际内容清空，待分配重新确认；不复制请假、现场日及审批状态 |
| 保存 | 保存草稿 | 可保存未填完内容，成功后显示保存时间；失败保留当前输入并提示重试 |

“全部可选对象”用于选取真实跨部门投入，不等于开放对象对应的成本或他人明细。已关闭对象不出现在新记录选择中，历史记录仍能查看；历史补录需要使用关闭对象时，由管理员按既定对象维护及封账规则处理。

### 3.3 提交前反馈

保存草稿允许不完整；送审必须校验。错误展示在对应日期和字段旁，直接说明需要补什么。

| 条件 | 展示与处理 |
|---|---|
| 实际工作 + 待分配不足应填基数 | “还有 2h 未说明去向”；该日工时不可送审，提供继续填报入口，不自动新增待分配 |
| 日填报合计超过 24h | 阻断该日工时送审，显示超出量 |
| 日实际工作超过 16h | 要求补充说明，允许送审；填报、审批和分析均保留红标 |
| 单条超过 8h | 警告并允许继续 |
| 内容不满足规则 | 定位条目，提示补充真实内容 |
| 只有合规现场日、没有工时 | 可单独送审现场日；如当日有应填基数，仍显示工时未完整 |
| 全天请假或非工作日且没有实际工作 | 无需虚构工时；符合条件的现场日仍可填写 |
| 缺审批人 / 工号匹配异常 / 已封账未获授权 | 保留记录，说明异常及处理责任人；不自批、不自动通过 |

交通投入直接记在对应项目，内容注明交通及事由；交通期间处理其他项目的时间从交通中扣除。只填小时数及内容，MVP 不引入起止时间轴，因此不能机械识别所有重复时段，真实性由员工说明与审批核实。

### 3.4 周提交

1. 员工打开“提交上周”，预览周一至周日的项目工作、非项目工作、待分配和现场日。
2. 按日显示校验结果、按对象显示预计实际审批人。异常直接定位缺项或负责人配置，不让员工自行选人绕过回避。
3. 点击“提交可送审记录”：完整日期的工时送审，符合条件的现场日独立送审；其他草稿保留。结果明确列出成功及未成功项，整周有缺项时继续标记未完成。
4. 系统按“人员 × 自然周 × 对象”组织审批包；工时和现场日取并集，只有现场日也生成包。
5. 只提交未提交的新条目或更正条目；已经待审批、通过或锁定的条目不重复进入送审。

这是 MVP 的提交交互约定，手动和截止后自动提交使用同一套校验。每日编辑主要保存草稿；上周送审和驳回后的补送审为主要提交场景，另保留现场日独立送审入口。

部分驳回后重提时，日级校验使用该日全部当前有效条目，包括已通过及待审批部分，只送审本次待提交项。例如已通过 6h、驳回 2h，改好后重提 2h 即可，不要求重新填写 8h。更正前的历史版本不重复加入当天合计。

### 3.5 员工侧状态与更正

| 状态 | 员工可做什么 | 页面提示 |
|---|---|---|
| 草稿 | 编辑、删除未送审条目、送审 | 尚未送审 |
| 待审批 | 查看接收人与进度 | 等待某人处理；MVP 不提供自行撤回，需联系实际审批人退回 |
| 已驳回 | 查看原因、修改后重新提交 | 只需处理驳回条目，已通过条目保持原结果 |
| 已通过 | 查看；申请审批人打回更正 | 不直接编辑已确认数据 |
| 已锁定 / 月份已封闭 | 查看原记录；申请指定范围补录、补审或更正 | 先授权解锁，再按原规则处理 |
| 争议处理中 | 查看双方说明和处理进度，补充本人说明 | 业务审批状态保留，争议单独标记，不计已确认成本 |

现场日已有待审批或已通过记录时，不能通过把地点改为“在司”删除该记录；更换归属项目或取消现场申报须走退回 / 更正流程，封账后先解锁。历史保留，但同一人同一天只允许一个当前有效现场日参与计费。

## 4. P02：审批与例外处理

### 4.1 待办列表

默认显示“待我审批”，按已超时、临近截止、其余待办排序，可按周、对象、人员筛选；已处理记录单独查看。

每行或每张卡片显示：对象、填报人、自然周、待处理工作工时、待分配时数、现场日数、截止时间，以及超 16h、回避、转交、争议等必要标记。“0h / 2 个现场日”是合法待办，不因工时为零被隐藏。

MVP 不提供跨多个审批包的一键全选通过。进入一个包后可整包通过或逐项处理，减少未经查看就批量确认的操作。

### 4.2 审批详情

```text
A 项目 / 张三 / 8 月 31 日—9 月 6 日
实际审批人：李四       周三 18:00 截止
工作 20h | 现场 3 天 | 本包金额：未审批部分为试算

工时条目
日期      小时    工作内容        标准费率/金额     状态
……

现场日（独立核实）
日期      现场事由     本项目/全天工作h     标准现场成本
周六      必要驻留     0/0，驻留说明待确认  待审批试算

辅助信息：本周其他对象工时合计；无具体对象名称
原始填报 / 处理历史 / 相关争议

[驳回所选并说明原因] [通过所选] [通过本包全部可处理项]
```

权限允许时展示费率及金额。实际指派获得的审批权限只覆盖该包；辅助信息只提供核实所需的其他对象工时总量，不披露其他项目名称、内容或成本。

| 操作 | 处理要求 |
|---|---|
| 通过 | 仅处理本人当前待办；确认时重新校验权限、回避、月份状态和有效标准，避免页面打开后状态已变化 |
| 部分通过 / 驳回 | 工时与现场日均可独立勾选；驳回必须有原因；已处理条目不重复处理 |
| 整包通过 | 按钮显示本次工时与现场日数量；存在争议、缺费率或封账限制时列明不可处理项，不静默全部通过 |
| 缺有效职级 / 费率 | 阻止相关计价条目通过，提示管理员补齐发生日标准；不使用零金额或当前标准代替 |
| 现场工时占比不足 50% | 提示“需复核时间分配”，可查看事由后确认，不自动驳回或扣款 |
| 日工作超过 16h | 展示日实际总量及说明；不只检查本包小时数 |
| 成功 / 并发变化 | 显示本次结果；重复点击不重复计费，已被处理的条目提示刷新 |

通过时将发生日有效职级、费率版本及金额固化。待分配不产生项目人工成本，现场日不依赖工时是否同时通过。

### 4.3 本人回避与转交

审批路由固定实现原 PRD 规则，不提供流程设计器：

- 普通成员：对象默认审批人。
- PM 填本人项目：填报人所属部门的指定负责人；仍为本人则转指定分管领导。
- 部门负责人填本人审批的部门事项：转分管领导。
- 分管领导本人、缺合适上级或上述候选人无效：由公司指定另一名非本人负责人，管理员登记。

路由无有效接收人时保留待送审数据，进入管理异常，不使用管理员自动兜底。实际审批人生成后写入审批包，消息与操作权限随此接收人走。

缺席或离职转交采用一个简单表单：原审批人、待办范围、业务指定的新接收人、依据与原因。管理员执行前预览条数；只转尚未处理项，保留已处理人的结论和时间，原接收人失去被转交项的操作权。永久默认审批人变更与已有待办转交分开执行。

### 4.4 工时争议

在相关工时条目提供“申请协调”，由员工或实际审批人填写分歧，保留原始投入及双方说明。争议作为记录附属处理单，不建设独立工单平台。

处理链为：**项目主责部门负责人协调 → 跨部门协调不成由分管领导裁定 → 按结论更正或完成业务审批**。此处依据项目主责部门，不是本人回避时的员工所属部门。

协调页仅包含相关条目、双方说明、处理人、结论、理由和时间；权限限于本次争议。事实已确认发生且归属正确的 8h，不因认为应当 4h 完成而压减。需要更正时保留前后版本并重新审批；封账后还需解锁。争议未结前不计入确认成本，也不影响同包无争议条目。

管理员可处理配置与流转问题，不作事实裁定；协调或裁定不通过自动“通过”按钮绕开本人回避。

## 5. 三个分析视图，覆盖五项报表能力

### 5.1 共用规则

所有分析页注明统计期间、确认状态和更新时间；金额统一称“标准成本”。未决条目及缺填情况要能点开查看，不能把暂时少计的金额当成项目完整投入。

- **当前分析**：以当前有效的已通过及已锁定数据展示确认结果；未决单列，若展示未审批金额则明确标为试算。未封账页面醒目标注“未封账”。已通过条目获准退回更正后，旧记录仅保留为历史，新版本在重新通过前不纳入当前确认金额，页面提示更正处理中；原正式月报金额保持不变。
- **正式月报**：只读版本，显示月份、版本号、生成时间和数据截止时间；默认最新已发布版，支持查看旧版及差异。
- **导出**：三个视图及其页签均能导出 Excel，权限与筛选范围一致。正式版本导出从版本快照取数，不实时拼接最新记录。
- **空值**：没有有效标准显示“缺少标准”；尚未确认显示“待确认”。已知应填基数为零时负荷显示“不适用”；现场占比按 5.4 区分已确认无工作与数据待完善。只有真实确认结果为零才显示 0。

### 5.2 P03：人员与执行情况

#### 页签一：时间负荷

默认最近四周，可切换日粒度，按部门、职级筛选。行是人员，列是周；点击格子展开该人该周期的时间构成及状态。

| 内容 | 展示方式 |
|---|---|
| 负荷 | 已确认实际工作 / 应填基数；分母为零显示“不适用” |
| 构成 | 项目工作、非项目工作、已确认待分配、请假、实际加班分别显示 |
| 数据完整且审批完成 | 使用负荷色阶；MVP 边界统一为 <80% 蓝、80%–110% 绿、>110%–130% 黄、>130% 红 |
| 未填完整或存在草稿、待审批、未处理驳回、争议 | 显示状态及已确认小时数，使用中性样式，不按低负荷着色 |
| 下钻 | 显示发生日期、对象、小时数、内容及状态；金额按独立成本权限决定是否可见 |
| 管理动作 | 可筛选持续超载或已确认待分配人员，导出用于现有部门会议 |

展示提示：“历史待分配时间不等于未来可用排期。”MVP 不依据热力图自动给人员贴“低效”“可调配”标签。

#### 页签二：填报与审批

默认显示上一个已到截止时间的统计周，并可按部门查看及时率、逾期人数、审批完成率、超时审批包和实际审批人名单。下方列出月度未决、解锁补录或更正次数、月报修订次数及处理原因入口。

为避免同一指标在不同页面口径不同，MVP 采用以下产品统计定义；这些是对原 PRD 指标的落地补充：

| 指标 | 统计定义 |
|---|---|
| 填报及时率 | 在该日次日 12:00 前，工时记录达到日级提交校验的人日数 / 应填人日数；统计期内应填基数 >0 的日期进入分母；不要求此时已经周提交或审批 |
| 逾期提交人数 | 该统计周在次周一 12:00 后首次送审记录的去重人数，含截止后自动提交；尚未提交者另列，不从名单中消失 |
| 审批完成率 | 截点前应处理的送审条目中已有通过或驳回结论的比例，包含工时与现场日；更正重提按新的送审轮次计，未结争议不算完成 |
| 审批超时包数 | 已过审批截止时间、仍有未处理项的审批包去重数；按当前实际审批人呈现，转交不重置原截止时间 |
| 缺填与未决 | 缺填按人员 × 日期列出；草稿、待审批、驳回未处理、争议按条目实际状态列出，避免把同一争议条目重复计总数 |
| 解锁与修订 | 解锁按授权事项去重计数，月报修订按新发布版本计数，均可追溯原因 |

通过、驳回数量须与审批完成率一起呈现，避免“全部驳回”被误解为数据已经可用。时限按系统配置及实际发生事件留痕；更改参数不改写既有及时性结果，迟到数据影响已发布月报时走修订。

### 5.3 P04：项目标准成本

默认展示本月未封账分析，部门负责人默认本部门主责项目，PM 默认本人负责项目。支持月、季度、年度、项目类型及主责部门筛选。

```text
项目标准成本   [本月] [未封账分析 / 正式月报] [范围筛选]
已确认标准总成本    标准人工成本    标准现场成本
提示：仍有待审批、驳回或缺填数据，当前金额尚不完整

项目    已确认工时   现场天数   人工成本   现场成本   总成本   参与人数
A 项目  ……
点击项目 → 参与人员 → 该项目工时与现场日、采用标准及处理记录

[未决明细] [查看费率标准] [导出当前范围]
```

核心字段为项目编码、名称、类型、主责部门、PM、已确认工时、标准人工成本、现场天数、标准现场成本、标准总成本、参与人数、未决提示。参与人数按已确认工时或现场日的人员并集去重；只有现场日的人员不能漏掉。

项目人员详情展示该人在本项目的工时、现场日及对应成本，不因跨部门参与而缺列。条目详情能追溯工作发生日、当日职级、有效费率版本、审批人和固化金额。

季度、年度的“当前分析”按选定发生日期区间统计。查看正式口径时汇总各月份所选的已发布版本，列出使用的月份和版本清单；其中某月未发布时标注缺失，不用未封账试算冒充正式月报。

仅有缺填日期而没有项目归属时，将其放在权限允许范围内的缺填名单，不把缺失工时猜测归给某项目。PM 不因此看到其无权查看的公司缺填明细。

### 5.4 P05：现场日复核

默认上月，异常置顶，支持人员、项目、部门、月份和“只看异常”筛选。一个视图同时提供明细与按项目 / 人员的汇总，覆盖原 PRD 的现场日台账和现场日项目工时占比。

| 字段组 | 必须展示的内容 |
|---|---|
| 基础 | 日期、姓名、字符串工号、部门、现场归属项目、现场事由 |
| 审批与成本 | 现场日状态、已确认标准现场成本；未通过金额若展示则标记试算 |
| 时间分配 | 本项目实际工作h / 当日实际工作总h、确认状态、比例、复核提示 |
| OA 比对 | 一致 / OA无单 / OA有单未填现场 / 项目不符，以及比对时间 |
| 处理 | 原始申报、审批记录、OA 依据、需要更正时的业务处理入口 |

仅在相关工时完整、审批完成且分母 >0 时展示正式比例；不足 50% 提示复核时间分配。分子分母均包含真实交通投入、排除待分配和请假。汇总使用合格行的分子合计 / 分母合计，并显示纳入计算的天数与待确认天数，不平均每天的百分比。

已确认必要驻留、没有实际工作的日期显示“不适用”，不触发低占比，但其现场天数和标准成本照常汇总。尚未补填实际交通的情况显示“待完善”，不能用“不适用”掩盖漏填。

OA 比对还须有独立的数据状态：**未比对 / 数据未到 / 身份待处理**。同步失败、未导入或身份解析失败不能标为“OA无单”。无现场记录的 OA 出差日也进入复核候选行，现场天数与成本仍为零，直到按真实情况补报并审批；系统不自动补记。

OA 未提供项目编码时只做人员与日期比对，并提示“未校验项目归属”。比对不直接拒绝审批、扣成本或阻止封账，异常及未核实情况随报告保留。导入 OA 出差清单和接口拉取使用同一套比对逻辑。

### 5.5 关键口径速查

| 口径 | 公式 / 边界 |
|---|---|
| 应填基数 | 当日工作日历基数扣减已审批请假，最低为 0；重叠请假不得重复扣减 |
| 填报合计 | 实际工作 + 待分配，不含请假；现场日不自动增加小时 |
| 工作负荷 | 已确认实际工作 / 应填基数；实际工作包括项目、交通及实际非项目工作 |
| 项目标准人工成本 | 已确认项目工时 × 发生日有效小时费率，逐条固化后汇总 |
| 标准现场成本 | 已确认现场日 × 发生日有效现场日标准；每人每个自然日最多 1 天 |
| 工作日加班 | 实际工作超过 8h 的部分；不能因半天请假将 4h 工作自动计为加班 |
| 非工作日加班 | 全部实际工作，包括交通；仅驻留休息为 0h |
| 现场日项目工时占比 | 该事由项目当天实际工作 / 当天实际工作总量；已确认无工作为不适用，待完善数据另行提示 |

默认参数变化需分别适用于其对应口径，不以“应填基数”替代所有公式中的 8h。费率按日标准 / 8 折算、加班系数 1.0，均继承原 PRD。

## 6. P06：月度封账与修订

月度封账是管理报告的固定截点，不代表当月所有记录已审核完。MVP 保留月报版本及差异，采用一个工作台完成例外处理。

### 6.1 工作台内容与角色

工作台展示月份、封账时点、最新已发布版本、已确认工时与现场日、缺填、各类未决、当前解锁事项及接入异常。

公司领导及其他报告阅读者按原权限查看版本；解锁仍限部门负责人、分管领导、管理员。MVP 对解锁范围采用以下具体设计：部门负责人限其主责项目和本部门非项目对象，分管领导限所辖范围，管理员可处理全局授权事项。新补录授权也指定对象及人员日期，防止授权扩展到其他项目。跨范围请求交有权人员处理。

### 6.2 固定流程

| 阶段 | 系统与用户动作 | 结果 |
|---|---|---|
| 封账前检查 | 管理者查看缺填、未决、缺标准和 OA 差异，跟进相关人员 | 不为等全部异常清零而无限延后截点 |
| 每月 10 日 00:00 | 按配置封闭上月；锁定已通过工时与现场日；保存相同截点的报告、明细与未决快照 | 发布该月 V1；有缺填或未决则明确标识数据不完整 |
| 封账后请求 | 申请人填写补录 / 补审 / 更正类型、人员日期、对象或记录、原因 | 请求进入有权人员处理范围，不直接开放整月 |
| 授权 | 有权人员核实范围后开放指定项，留存授权依据 | 只开放该事项；不产生审批通过或确认成本 |
| 处理 | 补审继续原流程；新增或更正重新送审；保持本人回避 | 保存新旧内容、业务结论和成本快照 |
| 修订发布 | 管理员检查本次事项结果，触发重新封闭授权范围及生成新版 | 获批项锁定，未获批项保持原状态并受月份封闭约束；发布 V2 及差异，V1 不变 |

修订中的当前数据与已发布报告分开显示；在新版发布前，默认正式月报仍是上一已发布版。没有业务通过的条目不能因“完成修订”而计入成本。即使本次最终未获批，也能关闭例外范围并保留处理结果。

OA 迟到请假、出差或更正数据进入差异待处理区，不能默默改变封账月份的基数、现场日或既有月报。跨月审批包逐条判断月份权限，整包通过不能绕过旧月份限制。

生成正式报告失败时显示任务失败及重试入口，不标记“已发布”；恢复后以一致截点完成报告。重复执行同一次封账或发布操作不产生重复版本、重复成本。

## 7. 管理功能与数据接入的最小设计

### 7.1 P07：人员与组织

人员列表支持姓名、工号、部门、状态筛选；人员详情集中呈现身份、组织、职级历史与审批职责。身份关联通过现有体系取得，本系统维护业务组织和角色。

| 数据 | MVP 必备要求 |
|---|---|
| 人员身份 | `user.id` 为内部稳定自增主键；`employee_no varchar(20)` 按字符串保存；兼容 `98123`、`XX12345`、`ZD23412` 及五位数字的前导零 |
| 身份变更 | 工号变更更新同一人并留痕；旧工号历史数据仍解析到原 `user.id`，不能按姓名合并或自动新建重复人 |
| 状态 | 离职停用登录及新业务操作，保留历史；提示仍未交接的审批待办 |
| 职级 | 当前职级、历史生效区间；初始导入必须包含生效日期；区间不重叠 |
| 部门 | 内部稳定 ID / 编码、名称、层级、状态；不使用企微部门 ID 作业务主键 |
| 负责人 | 支持部长与副部长多人、生效区间；指定回避承接人、分管领导及必要的公司指定人 |
| 调整 | Excel 或批量选择变更部门、负责人和职级；预览影响及生效信息，历史记录不随当前名单重写 |

已关联业务的人员、部门、对象采用停用或关闭，避免物理删除造成断链。组织变更的历史处理需明确记录；正式月报名称、归属与明细保持版本内原值。

### 7.2 P08 / P09：对象与标准

对象管理使用项目 / 非项目两个页签，字段包括编码、名称、类型、主责部门、默认审批人、来源、启用状态。普通员工只能选择，管理员及有权限的部门负责人维护对应非项目对象。每个部门预置待分配对象。

OA 来源项目的编码、名称、主责部门、PM 只读；手工项目独立标明来源。本人回避、临时转交不修改 OA 权威 PM。项目关闭后停止新选择，历史审批与查询继续保留。

费率页分“初 / 中 / 高职级标准”及“现场日标准”，列明生效区间和版本。管理员通过新增生效记录调整，历史行只读。缺失、重叠或无法覆盖业务发生日期时给出具体提示；列表及导入界面不自动填充未经确认的金额。

### 7.3 P10：导入与同步

保留固定数据模板与统一的“上传 → 预览 → 确认有效数据 → 结果 / 错误下载”流程。预览显示新增、更新、冲突和无效行，禁止身份不明时静默导入。失败行单列，不阻塞无关正确数据。

| 数据 | 最少业务字段要求，不代表已取得真实接口契约 | 兜底方式 |
|---|---|---|
| 人员及组织初始化 | 工号、姓名、身份关联、部门编码、在职状态；职级及生效日期、负责人配置 | 复用身份体系，业务信息由管理员导入 / 维护 |
| 项目 | 外部稳定标识 / 项目编码、名称、类型、主责部门编码、PM 工号、状态、变更信息 | 项目 Excel 模板及手工维护 |
| 请假 | 来源单据及明细标识、工号、覆盖日期或时段、每日有效请假时数、已审批状态、变更 / 撤销信息 | 从 OA 核实的已审批清单导入，保留来源依据 |
| 出差 | 来源单据标识、工号、起止日期、审批及变更信息；项目编码若可提供 | 已审批出差清单导入，运行同一比对逻辑 |
| 费率 | 职级或现场标准、金额、生效起止日期 | 管理员维护 / 导入 |

实际接口鉴权、字段名、时间语义、分页和增量机制需在《苍穹接口需求规格书》中确定；该配套文档当前未在项目目录提供。本设计不假定其已经完成，也不假定现有 SSO 必须直接返回工号。

数据接入页按来源展示最近成功时间、覆盖期间、失败数量及重试入口。人员匹配失败、部门 / 类型未映射、重复单据、来源冲突及封账后差异分别列出，管理员可定位单条原因。

- 项目与请假接口接入仍是首版目标；OA 联调延期时，试点可按原 PRD 的导入兜底运行，明确导入责任人及数据更新时间。
- 请假接口失败时沿用最近已核实数据并提示更新时间；缺失或错误请假必须通过核实清单补齐，不能把接口失败理解为所有人均无请假。
- 出差比对在数据覆盖期间完整可知时运行；数据未到显示相应状态，不能伪造“无单”结论。
- 自动同步项目到来时如发现疑似对应手工项目，进入冲突处理。管理员明确关联后保持原 WorkItem 及历史业务关联，不自动创建两个同名对象，也不静默覆盖手工对象。
- 源单据重复拉取、重试导入不重复扣假或增加现场成本；来源撤销、更新保留处理轨迹，封账后走差异及授权流程。

### 7.4 P11：提醒与系统参数

采用固定业务规则的可编辑列表，不建设自由编排能力。每条提醒可配置开关、时刻、工作日 / 每日 / 每周 / 每月日类型、适用阈值、接收范围及带变量的消息模板。

| 内置规则 | 默认时间 / 条件 | 默认接收人 |
|---|---|---|
| 当日未填 | 工作日 17:30 | 本人 |
| 前日补填 | 次日 10:00 | 本人 |
| 连续未填 | 连续 3 个应填日 | 本人 + 部门负责人 |
| 上周未提交 | 次周一 10:00 | 本人 |
| 截止自动提交 | 次周一 12:00 后 | 系统执行日级校验，失败项通知本人 |
| 审批待办 | 次周一 14:00 | 当前实际审批人 |
| 审批临期 | 次周三 15:00；截止为 18:00 | 当前实际审批人 |
| 审批超时 | 次周四 09:00 | 当前实际审批人 + 其上级 |
| 驳回 | 实时 | 填报人 |
| 月度封账 | 每月 10 日 00:00 | 系统执行，结果供有权人员查看 |

自动提交与封账是业务定时动作，在参数页配置；不把它们误做成仅发送一条提醒。消息跳转到具体待办，任务重试不重复送审或计费。已转交待办的消息只发当前接收人。

业务参数保留原 PRD 要求：单日上限 24h、红标 16h、默认应填 8h、步长 0.5h、周提交截止、审批截止、封账日。工作日历支持周末、法定休假及调休维护；计算使用同一公司业务时区 Asia/Shanghai。参数变更留痕并预览影响，不静默重算已发布报告。

## 8. 权限与可靠性底线

### 8.1 权限必须落实到数据和字段

| 身份 | 能看到的数据 | 明确限制 |
|---|---|---|
| 仅普通员工 | 本人工时、时间构成、负荷和流程状态 | 不返回费率与成本金额 |
| PM | 统一职级标准；本人项目全部参与人员的工时及标准成本 | 不查看其他项目成本；跨部门参与人不从本项目明细中剔除 |
| 部门负责人 | 本部门人员跨项目工时与负荷；本部门主责项目全部参与人成本 | 本部门人员在其他主责部门项目上的成本隐藏 |
| 分管领导 | 所辖部门人员及主责项目范围 | 不自动扩展全公司范围 |
| 公司领导 / 管理员 | 原 PRD 授权的全公司分析 | 公司领导不自动获得全部审批或解锁权；管理员不自动获得业务审批权 |
| 回避、转交或公司指定审批人 | 指定包及必要核实信息 | 不因此开放整项目；已有角色权限另行叠加 |
| 争议协调 / 裁定人 | 所处理争议及依据 | 不因此扩大报表权限 |

列表、详情、汇总、搜索结果、Excel、历史版本及消息链接均执行相同权限；不能只隐藏按钮而仍返回越权字段。历史版本不以“曾经可以看”为由绕过当前访问授权，也不因导出旧版而更换其快照内容。

### 8.2 最少保障能力

- 私有化部署，峰值 100 人同时填报；常规填报交互响应目标 <1s。性能验收记录测试环境、数据量和计时范围，报表导出展示独立进度，不用导出耗时冒充日常交互。
- 填报和审批适配手机；工作日 08:00–20:00 保障可用，自动封账等后台任务按配置时点运行。
- 保存失败保留输入；身份或来源异常不丢业务数据；批量处理逐项返回结果。
- 填报、修改、审批、转交、争议、标准变更、组织调整、解锁、封账与版本发布全程可追溯；记录操作者、时间、原因及修改前后内容。
- 数据库每日全量备份、保留 30 天；试点前完成一次备份恢复验证，包括报告版本与审核历史。
- 任何自动任务重试、重复点击或并发审批，都不应形成重复现场日、重复确认金额、重复扣假或重复正式报告。

## 9. 开发拆分与交付门槛

以下是可独立演示的交付包，不是工期承诺。每包覆盖页面、业务处理及验收；不把所有界面完成等同业务完成。

| 顺序 | 交付包 | 覆盖页面 / 能力 | 演示完成标志 |
|---|---|---|---|
| A | 登录、基础资料与每日记录 | P01、P07–P10 的基础维护及导入 | 两种工号登录同一身份体系；导入项目、职级和请假；完成真实工作、待分配及独立现场日草稿 |
| B | 周送审与业务核实 | P02、审批配置、转交、争议、提醒 | 一周拆成多个对象包，本人回避、独立现场日、部分驳回与再次提交跑通 |

| E（并行） | 企微能力验证与 OA 联调 | 身份、通讯录、消息；项目 / 请假 / 出差 | 固定接口能增量、重试、处理异常；自动数据与导入数据口径一致 |

SSO 接入及企微消息权限在 A / B 阶段完成验证，不等 E 最后再处理。OA 联调与 A–D 并行；接口未就绪时用核实后的导入数据继续。正式试点要求 A–D 全部完成，E 的每项必须注明已接入或采用哪个兜底，不把部分功能演示称为业务上线。

## 10. MVP 验收与试点

### 10.1 必过场景

验收数据中的单价为测试专用，不能用作上线费率。以下覆盖原 PRD 的 13 个关键场景，并增加最少的完整性与权限检查。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AT01 | `98123`、`XX12345`、`ZD23412`、带前导零的五位工号登录及导入；工号随后变更 | 按字符串正确关联；内部 `user.id` 不变，旧工号历史补拉可解析或进入明确异常 |
| AT02 | 应填 8h，项目 4h、部门事务 1h、待分配 3h | 全部通过后工作负荷 62.5%、待分配 3h；只计 4h 项目人工成本；未通过前提示未决，不标闲置 |
| AT03 | 半天已审批请假 + 4h 工作；重复拉取同一假单 | 应填 4h、负荷 100%；不重复扣假，不把请假加进工作或填报合计 |
| AT04 | 8 月 31 日工作，9 月 1 日调级或调价，9 月 3 日审批 | 用 8 月 31 日标准；快照可追溯，后续变更不改历史金额；缺标准时不能通过 |
| AT05 | 交通 6h 内含为 B 工作 2h，另为 A 现场工作 2h | A 6h、B 2h，总量 8h；现场 1 天归 A，无重复时间 |
| AT06 | 半天 / 当天往返；周末必要驻留且整周只有现场日；私人延长 | 前两种符合条件日期每天 1 天，独立送审计费；无工作比例不适用；私人延长不计 |
| AT07 | PM、部门负责人、分管领导本人填写自己负责对象 | 全部回避本人；无有效接收人保留异常，不自动通过；其他人的默认路由不受影响 |
| AT08 | 包内部分已通过后，原审批人离职，未处理项转交 | 已处理结论、人和时间不变；新接收人收到待办，原人失去被转交项操作权 |
| AT09 | 真实 8h 被认为合理耗时应为 4h；同包另一条无争议 | 不以效率为由压减事实；争议按主责部门协调并留痕，不影响另一条正常通过 |
| AT10 | 周末发生加班 / 交通 / 驻留，次周一送审并重复触发自动提交 | 归上周；按配置截止、推送和超时；不重复送审，不补造工作，不绕过日校验 |
| AT11 | 普通员工、PM、部门负责人分别查看、下钻及导出同一跨部门项目 | 员工无金额；PM 可看本项目所有参与人，不能越项目；部门范围按项目主责及人员负荷分别执行 |
| AT12 | 8 月条目在 9 月 10 日未决，9 月 12 日获准补审 | V1 未决且金额不含该条；授权后业务通过生成 V2；V1 原值与原未决仍能导出 |
| AT13 | 已确认现场日为 A 投入占比 <50%，其余为合理 B 支援；另一天仅驻留 | 前者只提示复核，不扣成本；后者不适用，仍计现场成本；汇总不平均日百分比 |
| AT14 | 日记录少于基数、超过 24h、实际工作超过 16h；重复内容；6h 已通过、2h 驳回后重提 | 不足或超上限阻断该日工时；超 16h 有说明可送审并持续红标；内容规则生效；有效现场日仍独立处理；重提 2h 时按全日 8h 校验，只审批这 2h |
| AT15 | 月份封账后新建记录、补审、修改请假基数；跨月包整包通过 | 未授权范围不能变更；跨月逐条控制；OA 迟到进入差异，不能影响正式版本 |
| AT16 | OA 失败 / 数据未到 / 人员解析失败 / OA 有单未填现场 | 不误报无单、不自动造现场日；导入兜底可完成复核，并标数据覆盖与来源 |
| AT17 | 连续点击通过、同时审批、重试导入、重跑封账；更改已送审现场地点 | 不重复成本、现场日、请假扣减或版本；界面能解释已处理或失败项；改地点不能直接删除现场日，须走退回 / 更正 |
| AT18 | 部门或人员归属变更、费率变更后查询历史正式版本；备份恢复 | 历史归属、采用费率和月报内容可复现，审批审计与版本一起恢复 |

### 10.2 试点安排与成功标准

沿用原 PRD 的 1–2 个部门、至少 2 名 PM 与 1 名部门负责人，建议试点四周；开始日期应覆盖一次真实月度封账，另用测试数据演示一次历史更正修订。周期未覆盖封账时顺延验证，不以周报代替月报验收。

| 维度 | 试点出口 | 全员运行目标 |
|---|---|---|
| 填报 | 连续两周及时率 ≥90%，常规日填报 ≤3 分钟 | 及时率 ≥95% |
| 审批 | 连续两周完成率 ≥90%，超时名单可追踪 | 完成率 ≥95% |
| 数据 | 人工抽核工时、负荷、现场日、采用费率和金额无误 | 每月产出可追溯的项目标准成本及人员分析 |
| 闭环 | AT01–AT18 通过，完成一次封账及一次修订演示 | 未决、补录、更正和版本可持续追溯 |
| 管理使用 | 至少一次部门会议实际使用成本和负荷数据，记录需核实或调整的事项 | 进入既有月度经营会议程 |

每天填报及时率和审批完成率只能证明流程执行，不能代替事实核实。试点中观察单日输入耗时、驳回原因及实际审批行为；若大多数记录未经核实就通过，先调整责任和管理机制，不以增加页面或功能作为解决方案。
