# 外网演示环境

2026-09-05：为同事远程试用现有 MVP 准备独立演示环境。使用当前真实前端和 Spring Boot 业务接口，没有另建模拟 HTML 产品。

## 访问方式

当前入口保存在 `.local/demo/url.txt`，访问账号与口令保存在权限为 600 的 `.local/demo/config.json`。不要把该文件提交到仓库或作为普通配置对外分发；给试用者只分享外网链接和访问口令。

- 电脑页面：外网入口 + `/admin/`
- 手机页面：外网入口 + `/h5/`
- 首次打开会显示网页内的“访问演示”表单，输入访问账号 / 口令，随后选择测试身份。Chrome 与微信使用同一入口，不依赖浏览器的 HTTP 认证弹窗。
- `98123` 为员工，`XX12345` 为项目经理，`ZD23412` 为部门负责人，`00123` 为管理员。都是独立测试账号。

2026-09-05 的员工记录准备了 4h 项目、1h 非项目和 3h 待分配草稿，以及独立现场日。前一日记录通过真实自然周流程送审，工时已由测试项目经理审批，现场日仍待单独审批，可用来演示二者独立性。日期、应填基数、请假与状态继续来自实际业务数据。

## 环境边界

2026-09-06 起，演示 API、worker、Nginx 和 Cloudflare Tunnel 统一由 `deploy/compose.demo.yml` 的四个容器运行。请求经 Quick Tunnel → Nginx → 容器网络内的 `api:8081`。API 与 worker 不映射主机端口；网关 `8090` 和隧道诊断 `20242` 仅绑定 `127.0.0.1`。只挂载两端 `dist-demo`，不暴露 Vite、源码、source map、Actuator 或私有导出目录。

演示使用原 `worklog_demo` 数据库和只获该库权限的 `worklog_demo` 账号；Redis 会话使用 `worklog:demo:session`，Cookie 为 `WORKLOG_DEMO_SESSION` 且带 Secure / HttpOnly，`.local/demo/exports` 原目录挂载为容器的 `/app/exports`。API 与 worker 使用同一独立制品 `.local/demo/backend.jar`，以当前用户的 UID/GID 运行，根文件系统只读。启动脚本从私有配置生成权限为 600 的 `.local/demo/backend.env`，不把口令写入 Compose 文件。原 `worklog` 开发记录不受演示写入影响。

页面、assets 与 API 均经 Nginx `auth_request` 验证服务端演示访问许可，全部设置 no-store。仅访问表单及设计 Token CSS 公开；内部许可检查不对外开放。表单沿用现有 Spring Session / Redis 与 CSRF，成功验证后轮换会话 ID；访问口令不放进 URL、浏览器存储或前端构建产物。Cookie 保持 Secure / HttpOnly / SameSite=Lax。页面跳转保留 HTTPS，HTTP 访问经网关跳回 HTTPS。

访问表单仅在 `local` 且显式开启 `APP_DEMO_ACCESS_ENABLED` 时启用，启动脚本从私有配置读取原有访问账号与口令；非 local 不允许开启。POST 访问表单按整个临时演示入口限制频率（30 次/分钟，额外突发 20 次），不影响业务提交。业务会话、CSRF、身份权限与原封账规则继续生效；退出测试身份会销毁原会话，仅把演示访问许可带入新会话，可重新选择身份。演示构建仍要求后端明确启用测试登录；普通 production 构建关闭测试身份入口。

此前的 Basic Auth 入口在微信内可能直接显示 401；现已改成网页表单。访问许可失效时，整页刷新会回到表单；API 返回 `401 DEMO_ACCESS_REQUIRED` JSON，不会把登录 HTML 当作业务响应。登录后的业务权限错误仍原样返回。

容器采用 `restart: unless-stopped`，关闭开发终端或 Codex 不会带停演示进程；进程退出后由 Docker 重新启动，显式停止则保持停止。电脑休眠、断网或 Docker 退出期间仍无法访问。隧道进程重启会生成新地址，不能恢复旧临时域名；重新执行统一启动脚本会读取当前隧道本次启动日志并更新分享说明。Cloudflare 对 Quick Tunnel 不保证持续可用，适合临时预览：[官方说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。长期固定链接应使用稳定服务器和固定域名。

## 更新与停止

启动、恢复或获取当前链接：

```sh
python3 scripts/start-demo-preview.py
```

脚本复用已准备的制品与独立数据库，不重新构建或初始化数据。已有容器运行时，重复执行保持容器与链接不变；若隧道此前重启，则更新 `.local/demo/url.txt` 和 `.local/demo/分享说明.txt`。分享说明含口令，勿提交到仓库。

停止演示：

```sh
python3 scripts/stop-demo-preview.py
```

这会停止四个演示容器并清理旧入口记录，不停止原开发服务及 MySQL / Redis，也不删除任何数据卷。

更新前端：

```sh
cd frontend
npm run build:demo
```

demo 产物与普通 `dist` 分离。部署配置为 `deploy/nginx.demo.conf` 和 `deploy/compose.demo.yml`。需要查看运行状态与日志时：

```sh
docker compose -f deploy/compose.demo.yml ps
docker compose -f deploy/compose.demo.yml logs --tail 30
```

不再同时手动启动旧的本机演示 API / worker / 隧道，避免重复 worker。更新后端制品前先停止演示，替换 `.local/demo/backend.jar` 后再运行统一启动脚本。正式长期部署仍沿用公司 HTTPS、正式鉴权和独立基础设施方案。
