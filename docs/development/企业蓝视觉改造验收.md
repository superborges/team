# 企业蓝视觉改造验收

日期：2026-09-05。范围：现有 MVP 前端换肤及相关展示回归。

## 依据与审计

已阅读 `docs/design/timesheet_design_system_v1/CODEX_HANDOFF.md`、`DESIGN_SYSTEM.md` 和其 PRD 参考的 §3.1、§4.2–4.4、§5.5、§6.1。设计图与 HTML 仅供视觉参考，未接入为生产页面。

改造前为深墨蓝侧栏 / 顶栏、青绿主色、H5 540px 最大宽度，现场日嵌在概览内，保存和周送审分散在不同位置。现采用企业蓝主题、浅色导航、1120px 最大填报区，独立现场卡与统一操作层级。概览增加项目 / 非项目的真实分类，保留实际工作汇总和草稿口径说明。

前端仍是 Vue 3.5.42、Vant 4.10.2、Element Plus 2.14.5。无新增依赖、后端改动、数据迁移或接口调整。

## 业务保持情况

- 保存仍是显式保存草稿；自然周仍按周一至周日预览、提交，待审批与已处理条目不重复送审。
- 现场日保留归属项目、事由、独立状态及独立送审入口。零工时和工时不足不会被视觉层连带禁止现场送审。
- 应填基数、请假、步长、上限、红标阈值来自现有业务数据与规则；未把设计图的日期、8h 或其他样例值写入业务。
- 项目 4h + 非项目 1h + 待分配 3h 显示已说明 8h、实际工作 5h。请假不重复计入；零基数显示无最低要求。审批状态与时数完整度分别呈现。
- 忙态、失败保留输入、版本冲突、跨日期更正、取消版本、争议限制、封账权限和菜单条件保留。未新增自动保存、撤回、工时补足或成本权限。
- 原生 H5 对象选择、管理端可搜索选择，以及现有快捷能力保持原状。本轮没有因 PRD / 演示中的控件建议扩展需求；历史对象不在当前目录时显示分类待确认，不猜测数据。

## 已执行验证

| 验证 | 结果 |
| --- | --- |
| 改造前浏览器基线 | 原有 8 项通过 |
| `cd frontend && npm run typecheck` | 两端通过 |
| `cd frontend && npm run build` | 两端生产构建通过 |
| `cd frontend && npm test` | 14 / 14 通过，包含原有 8 项和新增 6 项 |
| lint | 仓库未配置独立 lint 命令，未宣称执行 |
| 两端真实填报页 | 320 / 375 / 390 / 768 / 1024 / 1440px，全页宽度均等于视口；无全局横向滚动 |
| 共享管理页面 | 8 个只读管理页在 320 / 390 / 768 / 1440px 无全页溢出，密集表格在容器内滚动 |
| 原生弹窗 | 六种目标宽度无溢出，Escape 关闭后焦点回到触发按钮 |
| 主按钮 | 实际计算样式为白字 / `#1664FF`、圆角 6px，对比度 4.88:1 |
| 移动表单 | 主要输入文字 16px，主要触控区域至少 44px；只读文字保持可读 |

新增回归涵盖两端 4+1+3 与请假独立、长对象名称与三条记录、六种宽度、零工时现场独立送审与自然周预览、零基数与封账待审批、加载时不伪造零值，以及保存失败保留输入并可重试。原有测试继续覆盖权限、CSRF、版本冲突、取消版本、争议处理、批量预览冲突及不确定提交的幂等键。

检查中修复了两个视觉接入问题：通用原生控件 CSS 优先级压过主蓝按钮；输入失焦时固定栏切换位置导致保存点击落空。基础选择器使用低优先级匹配，操作栏不再依赖输入焦点切换位置。

真实截图使用当前本地 API 和已有 98123 员工的 2026-09-05 记录。只读脚本拦截所有非认证业务写入；截图没有改动工时、日历或审批状态。因本地 Docker 先前已停止，验证前恢复了原 MySQL / Redis 开发服务和既有数据卷。
