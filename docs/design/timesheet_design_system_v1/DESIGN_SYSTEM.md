# 工时与项目成本 · 企业蓝 Design System

**版本：1.0.0 ｜ 范围：现有 MVP 的视觉与交互呈现 ｜ 主题：浅色**

> 以已确认的蓝白设计稿为视觉方向，建立可复用的颜色、尺寸、组件与页面规则。它是本项目的自定义设计系统，不是企业微信官方设计规范，也不是一次业务流程重做。

## 0. 使用范围与依据

视觉依据是 `references/approved-visual.png`，现有页面依据是 `references/original-mvp.png`。业务依据是 `references/PRD_v1.3_source.md`，其正文版本为 v1.3，原上传文件名中的 v1 不代表正文版本。

本规范新增的颜色、间距、布局、动效与组件尺寸均是**设计决策**，不是 PRD 已经规定的数值。PRD 中已确认的业务术语与规则保持不变。现有代码与 PRD 冲突时，先记录差异，不以“页面美化”为名静默修改后端逻辑。

优先级：**已确认业务规则与权限 > 本设计规范 > 示意图中的样例文字与数据**。不将此前 PRD review 中尚未被业务确认的建议自动变成需求。

## 1. 视觉方向

**清晰的企业蓝、白色工作区、浅灰页面、小圆角、细边框、中等信息密度。**

参考已确认图中的明亮蓝色选中态、浅色导航、规整表单与清晰层级；去掉图像生成中不必要的光晕、渐变与模糊。蓝色承担主要行动、导航选中和信息关联，绿色只表达已通过等成功状态。

| 采用 | 避免 |
|---|---|
| 小圆角白卡片、浅灰页面、清楚的行列关系 | 深色大面积顶栏、玻璃拟态、彩色渐变背景 |
| 一个操作区域一个主按钮 | 保存、提交、查看进度同时使用实心主色 |
| 文字＋图标表达状态 | 仅靠小圆点颜色、背景颜色表达业务结论 |
| 对齐、留白和字号区分层次 | 多层阴影、装饰插画、超大数字抢占填报空间 |
| 复用现有表单、路由和权限组件 | 为了换肤更换整个技术栈、组件库或业务结构 |

## 2. 颜色系统

`tokens.json` 是数值来源；`styles/tokens.css` 提供同名 CSS 变量。所有变量使用 `--ts-` 前缀，避免影响现有工程。

### 2.1 主色与中性色

| 用途 | Token | 色值 | 使用规则 |
|---|---|---|---|
| 主色 | `--ts-color-primary` | `#1664FF` | 主按钮、日期选中、开关选中、焦点轮廓 |
| 主色悬停 | `--ts-color-primary-hover` | `#1256DC` | 主按钮 hover，不用于移动端的唯一反馈 |
| 主色按下 | `--ts-color-primary-active` | `#0F49BC` | active |
| 浅蓝底 | `--ts-color-primary-soft` | `#EAF2FF` | 导航选中、项目标签、信息提示底色 |
| 蓝色文字 | `--ts-color-primary-text` | `#1259D5` | 链接、浅蓝背景上的小字；不直接用主色替代所有链接 |
| 页面底色 | `--ts-color-page` | `#F5F7FA` | 工作区底色 |
| 卡片底色 | `--ts-color-surface` | `#FFFFFF` | 内容容器、表单 |
| 次级底色 | `--ts-color-surface-subtle` | `#F8FAFC` | 表头、只读分组、轻量数据块 |
| 强调文字 | `--ts-color-text-strong` | `#172B4D` | 页标题、关键数字 |
| 正文 | `--ts-color-text` | `#1F2937` | 主要信息、表单内容 |
| 次级文字 | `--ts-color-text-secondary` | `#526176` | 标签、次级说明 |
| 辅助文字 | `--ts-color-text-muted` | `#667085` | 提示、时间信息；不再继续降低其不透明度 |
| 容器边框 | `--ts-color-border` | `#E5E9F0` | 卡片、表格外框；不是必需识别的输入边界 |
| 分隔线 | `--ts-color-divider` | `#EDF0F5` | 分组内部 |
| 控件边界 | `--ts-color-control-border` | `#8291A7` | 必须辨识的输入轮廓、未选复选框边界；比容器边框更明确 |

`#1664FF` 是为本项目选定的企业蓝，不宣称它是企业微信官方品牌色。蓝色实心按钮使用白字；浅蓝背景使用较深的 `primary-text`。

### 2.2 语义色

| 语义 | 文字 / 图标 | 背景 | 典型用途 |
|---|---|---|---|
| 信息 / 待审批 | `#1259D5` | `#EAF2FF` | 已送审、等待处理、一般信息 |
| 成功 | `#087A52` | `#E8F5EE` | 已通过、操作成功 |
| 警告 | `#9B5A00` | `#FFF4E5` | 即将超时、尚待核实、非阻断提示 |
| 错误 / 风险 | `#C1323E` | `#FFF0F0` | 已驳回、阻断错误、需要重点核实的超长工时 |
| 中性 | `#526176` | `#F2F4F7` | 草稿、已封账、非项目、待分配类别 |

**待分配时间不是错误或失败。** 其类别默认使用中性标签，只有存在独立的异常依据时才出现警告。项目/非项目是“类别”，待审批/已通过是“流程状态”，两类标签不能混用。

人员负荷热力图沿用 PRD §6.4 的蓝、绿、黄、红区间，不改成统一蓝色色阶；数据未确认时显示状态，不计算出低比例后直接标记闲置。阈值从现有业务配置或后端口径取得。

### 2.3 对比度质量目标

本项目目标：普通可读文字与背景对比度不低于 4.5:1；必要的控件边界、焦点提示和图形状态不低于 3:1。装饰性分隔线与不可操作的禁用控件单独处理。不能把“颜色看起来比较深”当成验证结果。

本包对常用色对进行了数值检查，结果见 `qa/QUALITY_CHECK.md`。这些是设计包色对检查，不代表实际产品已经完成可访问性验收。

## 3. 字体、数字与图标

使用系统字体，不加载在线字体、不随包分发字体文件。

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

| 层级 | 桌面字号 / 行高 | 移动端 | 字重 |
|---|---|---|---|
| 页面标题 | 24 / 32px | 20 / 28px | 600 |
| 区块标题 | 16 / 24px | 16 / 24px | 600 |
| 正文与导航 | 14 / 22px | 15 / 22px | 400，当前导航 500 |
| 表单标签 | 13 / 20px | 13 / 20px | 400–500 |
| 辅助说明 | 12 / 18px | 12 / 18px | 400 |
| 关键数字 | 28 / 36px | 24 / 32px | 600 |
| 表单输入文字 | 14 / 22px | 16 / 24px | 400 |

数字使用 `font-variant-numeric: tabular-nums`。数字与单位之间留 4px；单位使用辅助字号，不与数字同样加粗。工时按业务精度展示，整数可显示 `4 h`，不强制渲染成 `4.0 h`。货币保留业务规定的精度；无权限不显示金额，无数据使用“—”，不能伪装成 `0`。

图标采用统一线性风格，16/20px 两种常用尺寸，描边约 1.5–2px。优先复用项目已有的一套图标，不混用 emoji 或多种不一致的图标库。只有图标的按钮必须有可访问名称；移动端可点击区域不少于 44×44px。

## 4. 间距、圆角和层次

间距使用 `4、8、12、16、20、24、32、40、48px`，2px 仅用于光学校正。禁止在业务页面堆叠零散的 13px、19px 等偶然间距。

| 项目 | 桌面 | 移动端 |
|---|---|---|
| 页面左右内边距 | 24px，大屏可 32px | 16px，320px 宽可 12px |
| 区块间距 | 24px | 16px |
| 卡片内边距 | 20px | 16px |
| 字段组之间 | 16px | 16px |
| 标签与输入框之间 | 8px | 8px |
| 同组按钮间距 | 8px | 8px |
| 输入框 / 按钮圆角 | 6px | 6px |
| 内容卡片圆角 | 8px | 8px |
| 对话框圆角 | 12px | 12px |

默认卡片无阴影，使用 1px 容器边框。悬浮菜单与对话框才使用阴影。固定操作栏可使用轻阴影与顶部边框，不使用渐变或透明毛玻璃。

## 5. 布局与响应式

移动端仍是主要填报入口，不将新设计变成仅桌面可用的后台。审批与报表可采用桌面更高密度布局。依据：PRD §6.1、§6.2、§8。

| 视口 | 导航 | 内容布局 | 控件 |
|---|---|---|---|
| 320–767px | 保留原 MVP 的三项顶部标签：我的工时 / 审批与协调 / 通知；管理入口按现有实现与权限处理 | 单列，四项构成数据用 2×2，周历七列完整保留 | 44px 高，输入文字 16px |
| 768–1023px | 可使用顶部导航或现有抽屉；不挤入完整侧栏 | 内容自适应，复杂表单可两列 | 40px，纯触控设备仍取 44px |
| ≥1024px | 顶栏 56px，左侧导航 200px | 填报内容最大 1120px，宽屏不无限拉长；报表可另设更宽容器 | 默认 40px |

侧栏行高 44px，水平内边距 16px。选中项使用浅蓝底、蓝色文字和细竖线；不以大块主色填满整条侧栏。菜单来源保持现有权限配置，不在 CSS 中模拟授权。

移动端不渲染缩小版桌面侧栏，不把导航压成没有标签的图标。主页面不能产生横向滚动。密集报表可在独立表格容器内横向滚动，不带动整页。

### 5.1 页面骨架

```text
顶栏 / 当前用户
导航（桌面侧栏；移动顶部标签）
  页面标题 + 填报规则
  周日期选择器
  当日概览：日期 / 日类型 / 填报完整度 / 审批状态
  时间构成：项目工作 / 非项目工作 / 待分配 / 请假
  现场日：独立区块，已选现场时展开
  当天记录：条目卡片 + 添加记录
  操作栏：保存草稿 / 预览本周送审
```

推荐让现场日位于当天记录之前，保持 MVP 的业务顺序；样式沿用已确认图的轻量白卡。不要将“现场日”塞进语义模糊的“其他信息”。未来调整模块顺序应单独做体验确认。

## 6. 基础组件

### 6.1 Button / 按钮

| 类型 | 外观 | 用途 |
|---|---|---|
| Primary | 企业蓝实心、白字 | 预览本周送审、确认送审等当前步骤的主要行动 |
| Secondary | 白底、边框、正文色 | 保存草稿、取消 |
| Text | 无边框、深蓝字 | 查看审批进度、复制上一工作日 |
| Danger | 红字；高风险最终确认可红底 | 移除、删除等明确的破坏性操作 |

桌面默认高 40px、水平内边距 16px；移动端高 44px。32px 紧凑规格仅用于确有需要的桌面表格工具栏，不用于主要填报动作。

必备状态：默认、hover、active、focus-visible、disabled、loading。加载时维持按钮宽度，文案如“保存中…”；请求失败恢复操作并保留输入，不跳转假成功页面。禁用原因在邻近文字或可聚焦提示中说明，不只靠 disabled 按钮上的悬浮提示。

### 6.2 Input / Select / Textarea

标签位于控件上方，避免仅用 placeholder 当标签。必填规则只按现有表单实现显示；只读值保持可读，不能整体淡化到看不清。小时数建议提供已有的 1h / 2h / 4h / 8h 快捷值；步长由配置传入，不从设计 Token 推导。

文本域最小 88px，可随内容展开。字数计数放右下角，错误放下方左侧。工作内容采用 PRD 中的最少字数与重复校验；待分配使用专用说明规则，不能把真实工作校验直接套在待分配上。

错误时显示红色边框、具体文字和 `aria-invalid`；说明用 `aria-describedby` 关联输入。输入过程中不反复报错，优先在离开字段或提交后提示；已出现错误后可随修正即时清除。后端错误映射回对应条目，并将焦点定位到首个错误。

归集对象使用可搜索选择器，分组沿用“我的项目 → 我的部门杂活 → 全部”。本包预览的原生选择器仅示范外观，不替代实际项目已有搜索组件。

### 6.3 Tag / Badge

默认高度约 22px，文字 12px，水平内边距 6px，圆角 4px。标签保持简短：项目、非项目、草稿、待审批、已通过、已驳回、已封账。

一个记录标题通常最多同时显示一个类别标签与一个审批标签。月份封账是独立约束，必要时可额外展示锁图标＋“月份已封账”，不据此覆盖原审批状态。

### 6.4 Card / 卡片

以“业务区块”为第一层卡片，内部记录卡片最多再嵌一层。标题左对齐，操作右对齐。移动端长标题换行，操作不能挤出屏幕；不用不断缩小字号维持一行。

卡片 hover 不整体上浮，输入表单卡片不显示“可整卡点击”的假暗示。只有真正可进入详情的只读列表行才使用整行交互。

### 6.5 Alert / Toast / Empty / Skeleton

持续性问题使用页面内提示：同步差异、应填基数待核实、封账限制、审批缺失。Toast 用于短暂的操作反馈，不能承担需要阅读和处理的关键错误。

空态写清下一步，例如“当天还没有记录”＋“添加记录”；对非工作日，不诱导用户为了填满页面而编造工作。加载骨架保留周历和概览结构；失败有重试入口，不能把请求失败渲染成 0 小时。

未保存、保存中、保存成功、保存失败是四个不同的界面状态。MVP 采用显式保存时，不因新样式显示“自动保存”。只有保存接口确认成功后才能展示“已保存”。

### 6.6 Dialog / Drawer

确认对话框宽 480px、长表单可 640px；手机使用可滚动的近全屏面板或底部面板，内容不超视口。对话框有标题、明确的取消与确认动作；打开后焦点进入，关闭后回到触发入口，键盘不能落到遮罩后。

不要为了美化将所有编辑改成弹窗。当前工时卡片默认在页面内编辑；复杂详情和已有审批进度适合沿用抽屉。

## 7. 业务组件与状态

### 7.1 WeekStrip / 周日期选择器

七列等宽，展示星期、日期、已说明工时或紧凑状态。桌面日格约 76px 高，手机约 72px 高；点击区域完整覆盖日格。日期顶栏保留周区间与上一周、下一周、日期跳转、今天。

**选中日期不等于今天。** 选中使用主蓝背景与白字；今天可用独立小标记或描边。不用同一个圆点同时表示今天和已通过。

日格的主任务是切换日期与提示填报情况。审批详情留在当日概览中，避免七列中挤满多套状态。

| 日期状态 | 展示 |
|---|---|
| 有应填要求但未填写 | “未填”，逾期才采用明确警示 |
| 部分说明 | 实际已说明小时数＋“待补齐”或简化标识 |
| 完整 | 小时数＋“已说明”，不自动显示“已通过” |
| 无填报要求 | “无需填报”，不标漏填 |
| 无工时但有现场日 | 显示“现场日”，不能误判为空白未填 |
| 数据加载失败 / 基数未确认 | “待确认”，不回退成零值 |

选择按钮提供完整可访问名称，例如“9 月 4 日，周五，已说明 8 小时”。生产组件的键盘方向键切换与焦点行为应复用成熟的现有日期组件。

### 7.2 DaySummary / 当日概览

第一层突出应填、已说明、尚差；第二层显示项目工作、非项目工作、待分配、请假四项。实际工作可用一行汇总说明表达，不与其子项并列让用户相加。

```text
填报时间合计（已说明） = 实际工作工时 + 待分配时间
实际工作工时 = 项目工作工时（含项目交通） + 非项目实际工作工时
请假只展示出勤信息，不加入已说明或实际工作
尚差 = max(应填基数 - 已说明, 0)
```

这些是 PRD §3.1、§6.1 已有口径的展示映射，不替代服务端计算。

基数为 0：显示“当日无最低填报要求”，已发生投入照常展示，不显示 `8 / 0`、`∞%` 或伪造的 100% 进度。基数大于 0 时，进度条仅表达说明完整度，视觉宽度可封顶 100%，文本仍显示真实小时数；超额说明不自动判为加班。

“填报完整”和“尚未送审 / 待审批 / 部分驳回”等分开呈现。顶部小时数若包含草稿，标明它是填报口径，不能冒充已确认投入或已确认成本。

### 7.3 TimeEntryCard / 工时条目

保留草稿的直接编辑体验，不强制改成必须逐条点编辑的折叠列表。

```text
记录 1   [项目] [草稿]                         移除
归集对象 [测试·智能制造实施项目       v]
类型     [实际工作]          小时数 [4]
工作内容 [完成现场设备调试与问题复核……]
校验或状态说明                           字数
```

桌面“类型＋小时数”同排；归集对象较短时可与小时数同排，但不能截断关键名称。移动端对象独占一行，类型与小时数用约 2:1 分栏；输入不足时退为单列。

草稿可编辑；待审批、已通过等遵循当前状态机提供只读展示和获准操作，不新增 PRD 未定义的撤回能力。已通过记录不能因为渲染了输入框就变得可修改。

待分配类别从所选对象得到，类型固定时展示为清楚的只读字段，不伪装成一个有多个选项的可编辑下拉。说明保持预置文案并允许按现有规则补充。

### 7.4 OnsiteDayCard / 现场日

标题使用“现场日”，包含“当天是否因项目出差”选择。帮助文字：“含出差交通日与必要驻留，按自然日记录；实际工时另行填报。”这是对 PRD §5.5 的界面化表达，不把现场误解为必须实际到场工作。

未选择现场：保留简洁的一行选择入口；选择后展开现场归属项目、现场事由、独立审批状态，以及“仅提交当日现场日”。必填条件、字数和校验调用现有业务规则，不在本规范另行发明。

已有现场日或发生校验错误时不能默认折叠。工时不完整不能连带禁止符合条件的现场日独立送审；零工时、周末、全天请假情形保留入口。

### 7.5 ActionBar / 操作栏

| 操作 | 桌面 | 手机 |
|---|---|---|
| 保存草稿 | 次按钮 | 固定底栏左侧，约 1/3 宽 |
| 预览本周送审 | 主按钮 | 固定底栏右侧，约 2/3 宽 |
| 仅提交当日现场日 | 现场日卡片内独立按钮 | 现场日卡片内，不能仅藏在无说明的更多菜单 |
| 查看审批进度 | 文字按钮 / 已有详情入口 | 状态区域或固定栏上方的清楚入口 |

周提交预览应沿用现有实现展示目标自然周和送审范围；本次美化不新建或改变审批包拆分逻辑。已有待审批与已处理记录不因点击主按钮被再次送审。

固定栏必须为内容留出底部空间，并加 `env(safe-area-inset-bottom)`。出现虚拟键盘时，以实际容器测试决定采用随视口调整或临时退出固定模式；不得挡住当前输入框、错误提示或保存操作。

### 7.6 状态映射与叠加

| 轴 | 状态 | 建议表现 |
|---|---|---|
| 填报 | 未完整 / 已完整 / 无最低要求 / 基数待确认 | 文字与进度单独表达 |
| 审批 | 草稿 / 待审批 / 已通过 / 已驳回 | 中性 / 蓝 / 绿 / 红标签 |
| 审批包 | 部分驳回 | 警告色标签，条目各自保留真实状态 |
| 月份约束 | 已封账 / 获准处理指定范围 | 锁提示＋具体可操作范围 |
| 保存 | 未保存 / 保存中 / 已保存 / 保存失败 | 操作栏邻近提示 |

不能只用一个 `statusColor` 推导所有状态。例如“8 月已封账＋条目待审批”必须同时显示，不把未决条目渲染为已通过。

## 8. 审批、报表和主数据页面的复用

### 审批

保持“周 × 对象”的审批包视图，工时与现场日分区。待分配单独说明，现场日可单独处理。整包操作、条目选择和驳回原因采用统一 Button、Checkbox、Dialog。

单日实际工作超过红标阈值的记录，填报、审批、报表统一使用红色提示。未审批金额使用“试算”标签；已确认使用快照，不能为了展示方便改用当前费率。来源：PRD §5.3、§6.2。

### 报表

表头高约 40px、数据行默认 48px；紧凑模式作为可选，不能强加给手机。名称左对齐、金额和小时数右对齐，汇总与明细单位一致。权限过滤在数据层和接口执行，隐藏列不是安全措施。

“标准人工成本”“标准现场成本”“标准总成本”使用完整名称；不得缩成会被理解为实际支出的“工资”“差旅费”。正式月报显式展示月份、版本和截点；未决数据使用提示而不是零填充。来源：PRD §5.1、§6.4、§6.6。

### 主数据

OA 同步字段的只读状态需要文字解释，例如“由 OA 同步，请在来源系统修改”。有权限的维护操作仍按既有规则提供；来源标签与审批状态标签区分。来源：PRD §6.3。

## 9. 动效与可访问交互

颜色、边框和展开过渡使用 120–180ms；不对整个页面持续执行 `transition: all`，不在数值更新时播放炫目的滚动动画。

键盘焦点使用 2px 主色实线＋2px 外偏移，不能全局移除 outline。控件具备标签，Tab 顺序与视觉顺序一致，动态保存反馈使用适当的 live region。尊重减少动态效果的系统偏好。图标既有文字时作装饰，不重复朗读。

## 10. 代码接入边界

`tokens.css` 只提供变量；`components.css` 是独立作用域的参考组件样式，不是必须替换现有组件库的要求。它使用 `.ts-app` 与 `.ts-*` 类名，不对整个项目的裸 `button`、`input`、`table` 做全局覆盖。

```html
<link rel="stylesheet" href="styles/tokens.css">
<link rel="stylesheet" href="styles/components.css">
<div class="ts-app">
  <button type="button" class="ts-btn ts-btn--primary">预览本周送审</button>
</div>
```

现有项目使用组件库时，优先通过其已安装版本的主题接口映射 Token，再给业务组件补少量类名。不要未经评估同时加入第二套 UI 库。媒体查询断点在普通 CSS 中显式书写，不能直接把自定义属性当作媒体查询条件使用。

不要将 `8h、16h、24h、0.5h` 等业务值放入颜色尺寸 Token；它们来自业务配置。本包 HTML 的数值只属于演示 fixture。

建议提取的业务组件：`AppShell`、`WeekStrip`、`DaySummary`、`TimeEntryCard`、`OnsiteDayCard`、`ApprovalStatusTag`、`ActionBar`。按现有框架实现，不要求特定语言、状态管理或组件库。
