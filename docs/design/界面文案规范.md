# Team 界面文案规范

用于统一员工端和管理端的页面名称、按钮及提示。业务定义沿用 PRD；接口字段、状态码、导入模板和历史数据不随界面改名。

## 统一用词

| 原用词 | 界面用词 | 使用说明 |
| --- | --- | --- |
| 归集对象 | 项目与事项 / 项目或事项 | 页面用“项目与事项”，选择字段用“项目或事项”；包含项目、非项目事项和部门待安排事项。 |
| 审批与协调 | 审批中心 | 同时包含审批记录、更正申请和争议处理，不局限于待我审批。 |
| 审批包 | 审批单 | 同一张单可以有多条工时或现场日记录，各条仍可独立处理。 |
| 送审 | 提交审批 | 已处于明确提交场景的按钮可简称“提交”。 |
| 人员负荷与履约 | 人员工时分析 | 页内区分工作量统计和填报、审批情况；不暗示绩效或合同履约。 |
| 现场台账与占比 | 现场统计 | 查看现场日、项目工时占比和 OA 出差记录核对结果。 |
| 来源覆盖核实 | 数据完整性核查 | 明确核对哪类数据、哪个部门、哪段日期是否完整。 |
| 费率标准 | 成本标准 | 人工及现场日的标准单价，用于成本分析，不代表实际工资或报销。 |
| 月报与修订 | 月度结算 | 封账、查看正式月报、申请修订和发布新版。 |
| 规则与运行 | 系统设置 | 填报规则、提醒、任务状态和操作记录。 |
| 待分配 | 待安排工作 | 当天尚无任务安排的时间，不是待审批状态。 |
| 已说明 / 尚差 | 已填 / 还需填写 | 日填报汇总中的时间，不表示已经审批通过。 |
| 未决项 | 未确认记录 | 包含草稿、待审批、尚未处理的驳回和未解决争议，不统称“待审批”。 |

## 容易混淆的业务含义

- **最低应填工时**：日填报页面的最低要求，已扣除核实过的请假。日历管理中的“应填工时（请假前）”是扣假前的值。
- **已填工时**：实际工作加待安排时间，包含草稿和页面上未保存的修改；不包含请假，也不代表已确认。
- **实际工作**：项目工作、项目交通和非项目工作，不包括待安排、请假或仅在出差地休息的时间。
- **现场日**：因项目出差的一个自然日，包含交通和项目需要的停留。与工时分开记录和审批，不自动产生工时或加班；工时未填齐时也可单独提交符合条件的现场日。
- **自然周**：周一至周日。提交本周记录时，系统分别检查各日期；部分日期不能提交时，其他符合条件的记录仍可提交。
- **OA 无记录**：必须先确认对应日期和部门的数据完整。上传成功不等于数据完整，没有查到记录也不直接等于没有出差。
- **审批完成率**：已到审批期限的记录中，目前已处理的比例，不是“按时审批率”。
- **封账和修订**：封账保留未确认记录的原状态；修订申请获受理后仍需取得具体处理权限，完成修改和审批后还需发布新版月报。旧版保留。

## 写法

按钮说清动作，如“提交申请”“确认授权”“发布新版月报”；减少笼统的“应用”“执行”“确认提交”。错误提示按“发生了什么 → 接下来怎么做”表达。保留期限、权限、部分成功和数据是否已保存等影响操作判断的信息。

页面不使用“路由”“承接范围”“服务端已记录”等实现用语。确有追溯用途的记录 ID、版本号保留，并标明其含义。人员、项目、事项的已有名称及用户填写的说明原样展示，避免改写业务数据。

本轮处理现有页面、服务返回提示和已知状态的中文名称；版本差异中的原始数据对比仍沿用现有展示方式，后续可单独改为按字段列出的变更明细。
